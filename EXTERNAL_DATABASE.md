# Using External PostgreSQL Database

This guide explains how to configure the pt-orchestrator to use an external PostgreSQL database instead of the containerized one.

## Option 1: Using External Database (Recommended for Production)

### Prerequisites
- PostgreSQL 15+ running externally (on host or remote server)
- Database created (e.g., `orchestrator`)
- Database user with full permissions on the database

### Configuration

Create a `.env` file in the project root with your external database connection details:

```bash
# External Database Configuration
DATABASE_URL=jdbc:postgresql://host.docker.internal:5432/orchestrator
DATABASE_USER=your_db_user
DATABASE_PASSWORD=your_db_password

# Application Credentials
GITHUB_TOKEN=your_github_token
JENKINS_URL=http://host.docker.internal:9090
JENKINS_USER=pt-orch
JENKINS_TOKEN=your_jenkins_token
```

**Note**: Use `host.docker.internal` to connect to services running on your host machine from Docker.

### Start Application (External Database)

```bash
# Start only the orchestrator app (without internal database)
docker-compose up -d orchestrator-app
```

The application will use the database connection details from your `.env` file.

---

## Option 2: Using Internal Database (Development)

If you want to use the bundled PostgreSQL container:

```bash
# Start with internal database
docker-compose --profile with-db up -d
```

This will start both the database and application containers.

## Examples

### Example 1: External PostgreSQL on Host Machine

```bash
# .env file
DATABASE_URL=jdbc:postgresql://host.docker.internal:5432/orchestrator
DATABASE_USER=postgres
DATABASE_PASSWORD=mypassword
GITHUB_TOKEN=github_pat_xxx
JENKINS_TOKEN=jenkins_token_xxx
```

```bash
# Start application
docker-compose up -d orchestrator-app
```

### Example 2: External PostgreSQL on Remote Server

```bash
# .env file
DATABASE_URL=jdbc:postgresql://db.example.com:5432/orchestrator
DATABASE_USER=orchestrator_user
DATABASE_PASSWORD=secure_password
GITHUB_TOKEN=github_pat_xxx
JENKINS_TOKEN=jenkins_token_xxx
```

```bash
# Start application
docker-compose up -d orchestrator-app
```

### Example 3: Cloud-Hosted Database (e.g., AWS RDS, Azure PostgreSQL)

```bash

DATABASE_URL=jdbc:postgresql://mydb.abc123.us-east-1.rds.amazonaws.com:5432/orchestrator
DATABASE_USER=admin
DATABASE_PASSWORD=cloud_db_password
GITHUB_TOKEN=github_pat_xxx
JENKINS_TOKEN=jenkins_token_xxx
```

```bash
# Start application
docker-compose up -d orchestrator-app
```

## Database Initialization

The application uses Spring Boot's Hibernate auto-DDL feature, which will automatically create tables on first startup. To manually initialize the database:

### Option 1: Let Spring Boot Create Tables (Default)

The application is configured with `spring.jpa.hibernate.ddl-auto=update`, so tables will be created automatically on first run.

### Option 2: Manual Schema Creation

If you prefer to create the schema manually:

1. Connect to your PostgreSQL database
2. Run the schema SQL (generated by Hibernate on first run, check logs)

---

## Verifying Database Connection

Check the application logs to verify successful database connection:

```bash
docker-compose logs orchestrator-app | grep -i "database\|postgres\|hibernate"
```

You should see logs like:
```
Hibernate: create table workflow_definition ...
HikariPool-1 - Start completed.
Started OrchestratorApplication in X seconds
```

## Troubleshooting

### Connection Refused

**Problem**: `Connection refused` or `Unknown host`

**Solutions**:
- For host database: Use `host.docker.internal` instead of `localhost`
- For remote database: Ensure firewall allows connection from your machine
- Verify database is running: `pg_isready -h <host> -p 5432`

### Authentication Failed

**Problem**: `password authentication failed`

**Solutions**:
- Verify `DATABASE_USER` and `DATABASE_PASSWORD` are correct
- Check PostgreSQL `pg_hba.conf` allows connections from the application
- Ensure user has proper permissions on the database

### Database Does Not Exist

**Problem**: `database "orchestrator" does not exist`

**Solution**: Create the database:
```sql
CREATE DATABASE orchestrator;
GRANT ALL PRIVILEGES ON DATABASE orchestrator TO your_user;
```

## Environment Variable Reference

| Variable | Description | Default | Required |
|----------|-------------|---------|----------|
| `DATABASE_URL` | JDBC connection URL | `jdbc:postgresql://orchestrator-db:5432/orchestrator` | No |
| `DATABASE_USER` | Database username | `postgres` | No |
| `DATABASE_PASSWORD` | Database password | `postgres` | No |
| `GITHUB_TOKEN` | GitHub Personal Access Token | - | Yes (for GitHub workflows) |
| `JENKINS_URL` | Jenkins server URL | `http://localhost:9090` | No |
| `JENKINS_USER` | Jenkins username | `pt-orch` | No |
| `JENKINS_TOKEN` | Jenkins API token | - | Yes (for Jenkins workflows) |
